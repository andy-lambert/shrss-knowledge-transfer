# AGENT_EXECUTION_FILE_STANDARD.md

## Purpose

Define the naming conventions, directory structure, and lifecycle for
files generated by AI agents during execution.

Goals:

-   deterministic ordering of artifacts
-   traceability of agent reasoning
-   machine‑parsable artifact structure
-   human readable review artifacts
-   compatibility across Cursor, Claude, and Codex

------------------------------------------------------------------------

## File Template

Populate the file following the agent execution file template: `@docs/ai/reference/AEM_AGENT_EXECUTION_TEMPLATE.md`

---

## File Naming Convention

- Use the following format to name the file: `YYYYMMDD-HHMMSS_TASKID_AGENT_STAGE_DESCRIPTION.ext`
- Use the **field definition**, **execution stages**, and **agent names** information below to generate the file name
- Example: `20260309-104512_T042_architect_research_dispatcher-cache-strategy.md`

------------------------------------------------------------------------

## Field Definitions

| Field             | Purpose                                                      | Example                     |
| ----------------- | ------------------------------------------------------------ | --------------------------- |
| `YYYYMMDD-HHMMSS` | deterministic ordering                                       | `20260309-104512`           |
| `TASKID`          | group files by execution                                     | `T042`                      |
| `AGENT`           | which agent produced it. *(**default** for **single-agent sessions**, and when agent is **directing tasking and activity** of subagents during **multi-agent sessions**)* | `orchestrator`              |
| `STAGE`           | reasoning phase                                              | `research`                  |
| `DESCRIPTION`     | human-readable topic                                         | `dispatcher-cache-strategy` |

------------------------------------------------------------------------

## Approved Execution Stages

| Stage            | Meaning                         |
| ---------------- | ------------------------------- |
| `bootstrap`      | repo analysis                   |
| `classification` | ontology classification         |
| `research`       | doc discovery                   |
| `architecture`   | system design                   |
| `implementation` | code generation                 |
| `validation`     | reasoning protocol verification |
| `review`         | code review                     |
| `documentation`  | final output                    |

------------------------------------------------------------------------

## Agent Role Identifiers

- `architect`
- `developer`
- `reviewer`
- `debugger`
- `doc`
- `orchestrator` (default for single-agent sessions, and when agent is directing tasking and activity of subagents during multi-agent sessions)

Additional roles may be used if defined in project documentation.

------------------------------------------------------------------------

## Directory Structure

**Save agent execution documents** in subdirectories of the following directory: `@Documentation/Generated/Task_Execution/agent-runs`

  - Set subdirectory name to `TASKID` as defined under *"Field Definitions"* below
  - Artifacts should be grouped by task execution.

**Example:**

```plain text
agent-runs/
  T042/
    20260309-103200_T042_architect_bootstrap_project-analysis.md
    20260309-103455_T042_architect_classification_dispatcher.md
    20260309-104112_T042_architect_research_dispatcher-caching.md
    20260309-104512_T042_architect_architecture_cache-strategy.md
    20260309-105201_T042_developer_implementation_dispatcher-config.md
    20260309-105712_T042_reviewer_validation_cache-rules.md
```

------------------------------------------------------------------------

## Run Manifest

Each run directory should contain a manifest summarizing the execution.

Example:

`agent-runs/T042/T042_run_manifest.md`

Example contents:

```plain text
TASK\
Implement Dispatcher caching rules

Agents\
architect\
developer\
reviewer

Artifacts\
20260310-103200_architect_bootstrap.md\
20260310-104512_architect_architecture.md\
20260310-105201_developer_implementation.md\
20260310-105712_reviewer_validation.md
```

------------------------------------------------------------------------

## Artifact Lifecycle

Typical artifact lifecycle:

1.  **bootstrap** -- repository understanding
2.  **classification** -- ontology classification
3.  **research** -- documentation discovery
4.  **architecture** -- design decisions
5.  **implementation** -- code generation
6.  **validation** -- reasoning verification
7.  **review** -- code review
8.  **documentation** -- final artifact

------------------------------------------------------------------------

## Compatibility Rules

Execution artifacts must:

-   use Markdown (.md)
-   remain readable by all AI runtimes
-   avoid proprietary formats
-   remain compatible with Git review workflows

------------------------------------------------------------------------

## Design Goal

This standard provides:

-   reproducible agent execution traces
-   auditability of AI decision making
-   structured collaboration across agents
-   deterministic artifact ordering
-   interoperability across agent runtimes
